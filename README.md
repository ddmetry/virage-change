# Virage Change

Сервис обмена криптовалют и рублей: клиентский сайт и админ-панель. Node.js 22, без внешних зависимостей (`node:http`, `node:sqlite`, `node:crypto`). Дизайн-система — в [DESIGN.md](DESIGN.md), результаты проверок — в [AUDIT.md](AUDIT.md).

## Быстрый старт (локально)

```bash
node -v            # нужен 22.5 или новее
npm run fonts      # необязательно: скачает Onest и Unbounded (нужен интернет)
DEMO=1 npm start   # сборка + сервер на http://localhost:3000
```

`DEMO=1` подставляет **демо-реквизиты и демо-адреса приёма**, чтобы можно было пройти весь путь заявки. Без `DEMO` реквизитов в базе нет, и клиент увидит «приём оплаты временно недоступен», пока вы не добавите настоящие.

При первом запуске в консоль печатается логин `admin` и одноразовый пароль (или задайте `ADMIN_PASSWORD`). Админка: `/admin/`.

Тесты: `npm test` (8 сценариев: деньги, курс, заявка целиком, права админа, CSRF, безопасность).

## Что настроить перед запуском в бою

1. **Админка → Реквизиты RUB**: карты/телефоны для приёма рублей (по одному или нескольким на способ, выдаются по очереди).
2. **Админка → Адреса приёма**: адреса для каждой сети (можно списком). Один адрес выдаётся одной заявке и освобождается через 24 часа после её завершения. Адрес проверяется на формат сети.
3. **Админка → Валюты → Резервы**: сколько монет доступно для выплат (или «не учитывать»).
4. **Админка → Валюты**: цены. Стартовые цены — только ориентиры. Для монет включён источник `coingecko` (обновление каждые 60 с, если сервер видит интернет); если курс не обновлялся дольше `rates_stale_min` минут, заявки по направлению блокируются. Для ручных цен ставьте источник `manual`.
5. **Админка → Настройки**: маржа, лимиты, время заявки, контакты поддержки, оператор (юрлицо/ИП — подставляется в документы), плашка и режим техработ.
6. Переменные окружения — в `.env.example` (`NODE_ENV=production`, `BASE_URL`, `TRUST_PROXY=1` за прокси, `TELEGRAM_*` для уведомлений).
7. Замените тексты «Правила обмена», «Политика конфиденциальности», «AML-политика» (`src/pages/*.html`) на согласованные с юристом — это шаблоны.
8. Логотип: сейчас круглый знак-заглушка в `src/partials/header.html`, `footer.html` и `src/assets/favicon.svg`. Замените и выполните `npm run build`.

## Как это работает

- **Заявка**: главная → `/order/` (сети слева и справа, адрес, почта, промокод, согласие) → `/pay/?id=…` (таймер, реквизиты, «Я оплатил», статус). Доступ к заявке — по секретному токену из ссылки (`#t=…`, в базе только хэш).
- **Статусы**: ожидает оплаты → проверка оплаты → выполняется / на проверке → выполнена; отменена, не выполнена, истекла. Переходы строго по таблице; «Выполнено» требует хэша выплаты. Все шаги пишутся в историю заявки и журнал.
- **Деньги**: только BigInt с фиксированной точкой (18 знаков), выплата округляется вниз до знаков валюты. Итог = цена пары × (1 − маржа − спреды) × (1 + промо) − комиссия сети. Лимиты — в рублёвом эквиваленте.
- **Реферальная программа**: доля от маржи с завершённых заявок приглашённых, выплата вручную (раздел «Рефералы»).
- **AML-проверка**: запросы обрабатывает человек; автоматических «оценок риска» нет.
- **Уведомления**: Telegram-бот администратору и e-mail клиентам через webhook (`MAIL_WEBHOOK_URL`). Без них статусы видны на странице заявки.

## Безопасность

CSP без inline-скриптов и стилей, `frame-ancestors 'none'`, HSTS в проде, HttpOnly + SameSite cookie, CSRF-заголовок для админ-запросов и проверка Origin, scrypt для паролей, ограничение частоты запросов, хэшированные IP, валидация всех входных данных на сервере, проверка контрольных сумм адресов (BTC/LTC/DOGE/EVM/Tron/Solana/TON), защита от path traversal, JSON-лимит 64 КБ. Ограничитель частоты живёт в памяти процесса — при нескольких экземплярах вынесите в общее хранилище.

## Деплой (пример)

```
# nginx
location / { proxy_pass http://127.0.0.1:3000; proxy_set_header Host $host; proxy_set_header X-Forwarded-For $remote_addr; proxy_set_header X-Forwarded-Proto $scheme; }
```
Запускайте `NODE_ENV=production TRUST_PROXY=1 node --disable-warning=ExperimentalWarning server/main.js` под systemd; каталог `data/` (SQLite + секрет сессий) нужно бэкапить.

## Что сознательно не входит

Спот-торговля, DEX, наличные, конвертер из исходного шаблона; английский язык; загрузка документов (KYC); QR-коды оплаты; SMTP (только webhook); автоматическая отправка выплат (оператор выплачивает вручную и отмечает заявку); автоматическая проверка поступлений (оператор подтверждает оплату). Логотипы монет — товарные знаки их владельцев, использованы для обозначения валют.

## Структура



## Публичный GitHub

Проект подготовлен для публичного просмотра: секреты не хранятся в репозитории, `.env` игнорируется, пример конфигурации находится в `.env.example`. Сгенерированный `public/` не коммитится — он создаётся командой `npm run build`.

Для проверки интерфейса без реальных реквизитов используйте `DEMO=1 npm start`. Это демонстрационный режим; он не выполняет реальные платежи или выплаты.
